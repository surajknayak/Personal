Why this matters

Good retrieval starts with good data.

RAG does not magically understand an entire PDF. The document is parsed, divided into chunks, represented as embeddings, and indexed so relevant pieces can later be retrieved.

What happens?

Query → embedding → search

Your query is represented in vector space and matched against the knowledge base. Keyword matching complements semantic similarity for exact terms such as "API v2".

4. Augmentation

CONTEXT
Important distinction

Augmentation ≠ just rewriting the question.

The system combines the user query with retrieved context, instructions, metadata and potentially conversation history to create the input that the LLM receives.

Knowledge ingestion

3. Re-ranking

Improve precision after retrieval

RERANK
Recall → Precision

Retrieval finds candidates. Re-ranking picks the best.

A production RAG system may retrieve 20 candidates and then use a re-ranker to identify the 3–5 chunks most relevant to the exact query.

Key concepts

Remember these for interviews

01

Embeddings

Convert text into numerical vectors that capture semantic meaning.

02

Hybrid Search

Combine semantic similarity with keyword/exact-match retrieval.

03

Re-ranking

Re-score retrieved candidates to improve relevance before sending context to the LLM.

04

Grounding

Give the model relevant source material so its response is anchored to the knowledge base.
